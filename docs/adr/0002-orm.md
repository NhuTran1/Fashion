# ADR-0002 — Prisma ORM 7 cho MySQL InnoDB

**Trạng thái ACCEPTED.** Chủ dự án chọn Prisma ORM 7 và [nghiệm thu M1-02](../../tracking/WORKLOG.md#2026-11-20--m1-02--nghiệm-thu) ngày 2026-11-20. [Xác nhận lựa chọn](../../tracking/WORKLOG.md#2026-11-20--m1-02--chọn-prisma-orm-7).

## Bối cảnh

[Architecture v1](../02-ARCHITECTURE.md) yêu cầu một NestJS modular monolith và MySQL InnoDB. Orders chịu trách nhiệm về giao dịch checkout và hủy, còn Inventory quản lý tồn kho và biến động. Chủ dự án ưu tiên dễ đối chiếu mô hình dữ liệu, dễ review TypeScript và học backend qua các luồng thực tế.

## Phương án đã xem xét

- **Prisma ORM 7** dùng schema tập trung, client sinh kiểu và migration SQL có phiên bản. Schema giúp đối chiếu model, quan hệ và kiểu dữ liệu. Cần thêm bước sinh client, adapter MySQL và cấu hình CLI.
- **TypeORM + mysql2** đáp ứng yêu cầu MySQL với entity theo module, repository tích hợp NestJS và EntityManager theo giao dịch. Phù hợp khi nhóm ưu tiên mô hình entity/repository của NestJS. Với mục tiêu học và rà cấu trúc dữ liệu hiện tại, schema tập trung của Prisma có lợi thế.

## Quyết định

- Dùng **Prisma ORM 7 + MySQL InnoDB** cho MVP A. Khi scaffold, kiểm tra và cố định bộ phiên bản Node.js, NestJS, TypeScript, Prisma CLI/client, adapter và MySQL tương thích. Kiểm tra cấu hình module, kết nối local, bước sinh client và khả năng chạy build. Node quan sát được là v24.14.1. Phiên bản này chưa được chốt cho scaffold.
- Dùng Prisma Migrate với lịch sử migration SQL có phiên bản trong Git. Review SQL, giữ lịch sử đã áp dụng và kiểm chứng migration trên MySQL dùng riêng cho kiểm thử. Ở môi trường dev, chuẩn bị shadow database khi cần cho quy trình Prisma Migrate. Schema logic vẫn do M1-05 chốt.
- Giữ tiền ở `DECIMAL(12,2)` theo [mô hình dữ liệu](../03-DATA_MODEL.md). Khi triển khai, dùng kiểu Decimal và phép tính phù hợp, tránh ép qua JS number để tính tiền. Kiểm tra độ chính xác khi lưu và đọc snapshot.
- Orders mở một interactive transaction. Mọi ghi đơn, dòng hàng và tồn thuộc giao dịch phải dùng cùng transaction client. Inventory chỉ trừ khi tồn đủ và xác nhận đúng một dòng cập nhật. Nếu một SKU thiếu tồn, rollback toàn bộ.
- Checkout lặp cùng yêu cầu và key theo Customer phải trả về cùng một đơn mà không trừ tồn thêm. Hủy hợp lệ chuyển trạng thái, hoàn tồn và ghi biến động trong cùng giao dịch. Cơ chế khóa, ràng buộc và retry thuộc M1-05/M1-06.

## Hệ quả và bằng chứng triển khai

- Dễ đối chiếu mô hình logic, schema Prisma, migration SQL và truy vấn TypeScript. Khi merge thay đổi schema, review cả schema và lịch sử migration để phát hiện xung đột về dữ liệu.
- Gọi Prisma Client toàn cục trong nhánh đang chạy giao dịch có thể đưa thao tác ra ngoài rollback. Integration test cần kiểm chứng bằng MySQL InnoDB.
- Khi triển khai, kiểm chứng sinh client, kết nối và migration trên DB thử nghiệm. Kiểm thử tiền Decimal, hai checkout tranh tồn bằng 1, rollback khi một SKU thiếu tồn, checkout lặp và hủy lặp/đồng thời. Kiểm thử ứng dụng hiện NOT RUN.
